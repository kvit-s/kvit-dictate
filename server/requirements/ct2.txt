# WHAT IT IS FOR
#   The `faster-whisper` backend (server/kvit_asr/backends/faster_whisper.py):
#     * Systran/faster-whisper-large-v3          (row E  — batch accuracy reference, ~3.1 GB)
#     * Systran/faster-distil-whisper-large-v3   (row E′ — distilled, ~1.5 GB)
#   CANDIDATES.md §4 puts both in the SECOND TIER: batch accuracy references and the cheapest
#   CPU-side fallback, deferred until Phase 1 picks 1–4 have run. So this environment does not
#   need to exist yet, and creating it early buys nothing.
#
#   Its one structural virtue is that it needs NO PYTORCH. That is why row E gets its own env
#   rather than being added to the venv that already has Whisper working: plan.md §5.1 makes
#   ..\wan-dancer\.venv read-only for this project, and "faster-whisper looks compatible" is
#   exactly the reasoning §5.1 reverses revision 1 on.
#
# APPROXIMATE DOWNLOAD SIZE
#   ~150 MB of wheels for a CPU-only install (estimate: ctranslate2 is the bulk of it, plus av,
#   tokenizers, onnxruntime and huggingface_hub, which faster-whisper pulls in transitively).
#   A GPU install needs the CUDA 12 + cuDNN 9 runtime DLLs on PATH; if they are supplied by the
#   nvidia-* pip packages instead of a system CUDA install, add ~1.5 GB (estimate) — see the
#   commented lines at the bottom. Model weights are NOT included and are NOT downloaded by the
#   sidecar: they live in the shared HF_HOME (c:\apps\llama-swap\gguf\hf) and a human fetches
#   them once (plan.md §1.9).
#
# ─── PROVISIONAL PINS — READ THIS BEFORE BLAMING THE PACKAGE ─────────────────────────────────
# Written by hand, like requirements/onnx.txt, from bench/CANDIDATES.md and from what is known
# about this machine. They were NOT produced by a resolver and NOT checked against any package
# index: Phase 0A installed nothing and downloaded nothing (CANDIDATES.md §6 item 7), and
# nothing has changed that. A line marked UNVERIFIED may name a version that does not exist; the
# failure mode is a loud "no matching distribution", which is the intended behaviour — the pin is
# wrong, not the package. Replace this file wholesale in the first installing session:
#
#   set UV_CACHE_DIR=D:\uv-cache
#   uv pip compile --python-version 3.12 requirements\ct2.txt -o requirements\ct2.txt
#
# UV_CACHE_DIR MUST BE ON D: — uv hardlinks packages from its cache into the venv, hardlinks
# cannot cross volumes, and a C: cache with D: venvs silently full-copies every package
# (plan.md §5.2 item 4).
# ─────────────────────────────────────────────────────────────────────────────────────────────
