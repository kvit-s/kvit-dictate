What kvit-dictate does to your machine
======================================

Read this before installing. It is shown here rather than buried, because three of the things below look, to an antivirus product, exactly like the things malware does - and you should hear it from the program first.

1. It reads every keystroke.

kvit-dictate installs a global low-level keyboard hook so that its hotkey works in whatever application you are typing into. That hook sees every key you press, everywhere. It uses them to recognise one chord and, while you are dictating, to let you edit the text in the pill before it is typed in. Keystrokes are never recorded, never stored, and never sent anywhere.

2. It types into other applications.

That is the whole product: it synthesises keystrokes into whatever window has focus. It refuses to do so into password fields, into windows running with higher privileges than it has, and into applications you have told it to leave alone.

Heuristic antivirus scanners recognise (1) and (2) together as the signature of a keylogger. That is a fair description of the mechanism and an unfair one of the purpose, and the honest answer is that you should decide whether to trust it - the source is public, and this build is not code-signed.

3. It starts a second program.

Two executables are installed. kvit-dictate.exe is the part you see; kvit-asrd.exe is a translator that turns your speech service's replies into something the first one understands. The client launches it, supervises it, and stops it when you quit - including if it crashes, because the child is held in a Windows job object that closes with it.

It launches nothing else. The program it starts is always kvit-asrd.exe in the folder kvit-dictate.exe was installed into, and no setting, file or environment variable can point that anywhere else.

You will not see a window for it. If you would rather run your own server instead, Settings has a second option and nothing is launched for you.

4. It sends your audio to a service you configure.

kvit-dictate does not recognise speech itself. You give it the address of a speech service you run, and it streams 16 kHz audio there while you hold the hotkey. There is no cloud service, no telemetry, and no account. Nothing is sent until you press the hotkey, and nothing is sent anywhere except the address you typed.

That audio is sent unencrypted, and the service is not asked who you are. Run it on a network you control. docs/setup.md explains how.

5. It does not work until you give it an address.

There is no bundled recogniser. Until you configure one in Settings, the hotkey will not open your microphone and the tray will say so.

What it does not do
-------------------

No cloud service. No telemetry. No account. No automatic updates, and nothing downloaded at run time. Recognised text is never written to a log unless you switch that on yourself, and that switch is compiled out of release builds entirely.

Where it puts things
--------------------

The program:  %LOCALAPPDATA%\Programs\kvit-dictate
Settings:     %LOCALAPPDATA%\kvit-dictate\settings.json
Logs:         %LOCALAPPDATA%\kvit-dictate\logs

Both executables go in the first of those. Settings and logs survive an uninstall unless you ask for them to be removed, so reinstalling keeps the address you configured.

Nothing is written outside your own user profile, and the installer never asks for administrator rights.
